# VS Code extensions PR 2 (gaps said plainly, Codex without its CLI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A person who uses VS Code's Codex extension without the Codex CLI gets a working Codex setup (rules, config, hooks, skills) and a clear list of what only the CLI adds; bootstrap offers the CLI as recommended, not required; the agent page and the configure skill ask about VS Code and say the same.

**Architecture:** `codex.py` gains an "extension mode": when no Codex CLI is on PATH but a same-side Codex VS Code extension carries a usable codex (0.161 or newer), `unavailable()` returns None, read-only `codex mcp list` calls use that bundled binary, and the plugin step is skipped with one line. `check.py` reports the missing CLI as a warning in that case. `bootstrap.py` asks before installing the Codex CLI next to the extension (`--without-codex-cli` says no without a terminal) and lists the gap in "Still to do". Docs follow.

**Tech Stack:** Python 3.11+ standard library; pytest with `fake_home` / `fake_runner`.

**Spec:** `docs/superpowers/specs/2026-10-17-vscode-extensions-design.md`, Part 2 (and PR 2). The spec's promise this plan has to make real: "An extension-only user who says no gets a clean run with these gaps listed, never a failure."

## Global Constraints

- Spec Part 2 question, verbatim: `Install the Codex CLI alongside VS Code (for /hooks and plugins)? [Y/n]`; "without a terminal `--install` installs it as today and the summary says why".
- Spec Part 2 example message: "VS Code's Codex extension does not load plugins: loadout's skills (loadout:configure, superpowers) and plugin hooks are missing there, and it has no `/hooks`, so Serena's hooks wait for your approval. Fix: use the Codex CLI alongside VS Code. `loadout bootstrap --install` installs it; then run `codex` once in VS Code's terminal and approve the hooks in `/hooks`."
- Codex minimum stays 0.161 (`codex.MIN_VERSION`); an extension whose own codex is older is not used and the reason says "update the extension".
- Extension mode only for a Codex extension on this side: a local window, or the Remote-WSL server in WSL (`vscode.extensions(..., look=False)`: no `cmd.exe` lookup on every call).
- Users with a Codex CLI see no change at all (every new path starts with "no codex on PATH").
- The Claude Code CLI stays as it is in this PR (its bundled binary as a runner is PR 3).
- External commands only through `runner.run` with argument lists; tests use `fake_home`/`fake_runner`; Conventional Commits, no attribution.

## Review Focus

1. A Codex CLI on PATH: nothing changes (no extension lookup, `codex` is the program, plugins install as before).
2. An extension whose own codex is older than 0.161, or gives no version: not used; the reason names the extension update; bootstrap's Codex step is skipped as today.
3. A Windows `codex` shim on PATH in WSL plus a Remote-WSL extension: today's "the codex on PATH is the Windows one" reason stays (the shim is on PATH, so extension mode does not start).
4. `--without-codex-cli` with a Codex CLI already installed: nothing is removed; the flag only stops an install.
5. Without a terminal and without `--install`: no question, and the missing line says "recommended", not "(required)".

```python
EXT_OLD = ("VS Code's Codex extension runs codex {version}; loadout needs 0.161 or newer: update the extension in "
           "VS Code (or install the Codex CLI: loadout bootstrap --install)")
PLUGINS_EXTENSION = ("plugins: not installed: VS Code's Codex extension loads none (use the Codex CLI alongside it "
                     "for them: loadout bootstrap --install)")
HOOKS_NO_CLI = ("approve the loadout hooks once in the Codex CLI's /hooks (VS Code's Codex extension has none), and use "
                "the CLI for plugin skills: install it with loadout bootstrap --install, then run `codex` in VS Code's "
                "terminal and /hooks")


def extension_state():
    """With no Codex CLI: (the VS Code Codex extension on this side whose own codex loadout can use, None), or
    (None, why not) when there is one but its codex is too old or gives no version, or (None, None) when none."""
    from . import vscode
    why = None
    for ext in vscode.extensions({"codex": True}, look=False):  # this side only: no cmd.exe lookup per call
        if ext.install.where == "windows" or ext.binary is None:
            continue
        version = vscode.bundled_version(ext)
        if version is None:
            continue
        if vscode.too_old(version):
            why = EXT_OLD.format(version=version)
            continue
        return ext, None
    return None, why


def program() -> str:
    """The codex to run read-only commands with: the CLI, else the VS Code extension's own (extension mode)."""
    if runner.have("codex"):
        return "codex"
    ext, _ = extension_state()
    return str(ext.binary) if ext is not None else "codex"
```

```python
def codex_cli_choice(install: bool, ask: Ask, interactive: bool, wanted: bool) -> tuple[str | None, bool]:
    """(the Codex CLI line to print or None, skip its install). Only when the Codex CLI is missing and VS Code's Codex
    extension on this side can run Codex: the CLI is recommended there, not required (spec Part 2)."""
    from . import codex
```
