**Goal:** Part 3 of the VS Code spec: a folder's or profile's settings that turn the Codex extension's WSL switch off are named (never edited); `bootstrap --vscode-path` puts loadout's tool folders on PATH for Remote-WSL windows in `~/.vscode-server/server-env-setup` (backup, `loadout restore`); with no `claude` on PATH, loadout runs the Claude Code extension's bundled binary for its own `claude plugin …` and `claude mcp …` commands.

**Tech Stack:** Python 3.11+, standard library only; pytest with the `fake_home` and `fake_runner` fixtures.

**Spec:** `docs/superpowers/specs/2026-10-17-vscode-extensions-design.md` (Part 3, Part 4)

## Global Constraints

- Python 3.11+, standard library only in `cli/loadout/`.
- Tests use `fake_home` and `fake_runner`; never the real `~/.claude`, `~/.claude.json`, `~/.codex`, `~/.config/loadout`; never a real `claude`/`codex`/installer.
- "Each fix is a plan: one line per change with its reason, the question in a terminal or a flag, a backup before the write, `undo: loadout restore <dir>`. Only the named key or lines change; a run that changes nothing touches nothing."
- "The Codex WSL switch … when a profile's or the folder's `.vscode/settings.json` sets it to `false`, that file wins; `check` names it, loadout does not edit it."
- "PATH for Remote-WSL windows (new, `--vscode-path`): a marked block in `~/.vscode-server/server-env-setup` that adds the PATH entries bootstrap gives the shell (mise shims, `~/.local/bin`). The file is created if missing (recorded as created) or the block appended; the user's lines stay. The plan says it takes effect after "WSL: Restart" or a reconnect."
- "The Claude Code CLI without `claude` on PATH: loadout runs the extension's bundled binary for the commands it needs (`claude plugin …`, `claude mcp …`); the plan names the binary. No VS Code file is written. A platform build without a bundled binary falls back to Part 2's CLI offer."
- "The session hook and the daily sync never write VS Code files."
- With an agent off (`targets.json`), nothing of that agent's extension is read.
- External commands only through `runner.run` with argument lists.
- Conventional Commits; no `Co-Authored-By` or other AI attribution.

## Review Focus

1. A `server-env-setup` the user wrote without a trailing newline, or with CRLF: the block goes after their bytes, which stay byte for byte (Task 2 test `test_vscode_path_keeps_a_file_without_trailing_newline`).
2. `bootstrap --vscode-path` run twice: the second run changes nothing and takes no second backup (Task 2 test `test_vscode_path_twice_changes_nothing`).
3. A tool folder added later (mise installed after the first run): the block is refreshed in place, the user's lines stay (Task 2 test `test_vscode_path_refreshes_its_block`).
4. The bundled binary disappears mid-run (the extension updated and VS Code removed the old folder): `run()` answers 127 "not found", never raises (Task 3 test `test_fallback_that_vanished_is_not_found`).
5. A folder `.vscode/settings.json` that does not parse: no override row and no exception (its own `VS Code settings` row says it is broken) (Task 1 test `test_broken_folder_settings_give_no_override`).

def wsl_switch_overrides(win_home: Path) -> list[tuple[str, Path]]:
    """Settings that turn the Codex extension's WSL switch off over VS Code's user settings on Windows: the open
    folder's .vscode/settings.json ("folder", it wins) and a profile ("profile", while it is active; which one is,
    is not on disk). loadout names them and never edits them."""
    found = []
    folder = folder_settings()
    if folder is not None and _is_file(folder):
        data = read_jsonc(folder)
        if data is not None and data.get(wsl.WIN_SETTING) is False:
            found.append(("folder", folder))
    try:
        profiles = sorted((wsl.vscode_settings(win_home).parent / "profiles").glob("*/settings.json"))
    except OSError:
        profiles = []
    for p in profiles:
        data = read_jsonc(p)
        if data is not None and data.get(wsl.WIN_SETTING) is False:
            found.append(("profile", p))
    return found


def override_text(kind: str, path: Path) -> tuple[str, str]:
    """(detail, fix) for one override of the WSL switch."""
    if kind == "folder":
        return (f"{path} sets {wsl.WIN_SETTING} to false, and a folder's settings win over your user settings: in "
                "this folder the Codex extension runs Codex on Windows",
                "set it to true in that file or remove it (loadout does not edit a folder's settings)")
    return (f"the VS Code profile settings {path} set {wsl.WIN_SETTING} to false: while that profile is active the "
            "Codex extension runs Codex on Windows (loadout cannot tell which profile is active)",
            "set it to true in that profile (Preferences: Open User Settings (JSON) with the profile active) or "
            "remove it (loadout does not edit a profile)")

```python
SERVER_ENV_QUESTION = ("Add loadout's tool folders to PATH for VS Code's Remote-WSL windows "
                       "(~/.vscode-server/server-env-setup, backup first)? [y/N] ")
SERVER_ENV_AFTER = 'takes effect after "WSL: Restart" in VS Code, or a reconnect'


def vscode_path_wanted() -> bool:
    """In WSL with VS Code's Remote-WSL server (~/.vscode-server): its windows run no shell startup file."""
    return wsl.detect() is not None and (paths.home() / ".vscode-server").is_dir()


def _home_tool_dirs() -> list[Path]:
    home = paths.home()
    return [d for d in paths.tool_dirs() if d == home or home in d.parents]


def setup_vscode_path(bk: Backup | None) -> str:
    """Add or refresh loadout's PATH block in ~/.vscode-server/server-env-setup; the user's lines stay byte for byte.
    Returns the line to print, "" when nothing changed."""
    from . import vscode
    dirs = _home_tool_dirs()
    if not dirs:
        return ""
    target = paths.home() / vscode.SERVER_ENV
    block = _path_block(dirs)
    line = _refresh_path_block(target, block, bk)
    if line is None:
        if target.exists() and bk is not None:  # an append is undone from the copy
            bk.save_copy(target, f"{target} before adding the tool folders to PATH")
        line = _add_block(target, block, bk, False, marker=PATH_MARKER, what="the tool folders to PATH")
    return line or ""


def _vscode_path_step(ask: Ask, interactive: bool, flag: bool, bk: Backup | None) -> None:
    """--vscode-path, or a yes in a terminal when a tool folder is missing from the Remote-WSL PATH; a block written
    earlier is kept current (spec Part 3)."""
    from . import vscode
    if not vscode_path_wanted():
        if flag:
            out.status("VS Code PATH", "--vscode-path applies in WSL with VS Code's Remote-WSL server "
                                       "(~/.vscode-server); nothing changed", "warn")
        return
    target = paths.home() / vscode.SERVER_ENV
    try:
        ours = PATH_MARKER.encode() in target.read_bytes()
    except OSError:
        ours = False
    if not (flag or ours):
        have = set(vscode.remote_path_dirs())
        missing = [d for d in _home_tool_dirs() if str(d) not in have]
        if not missing or not interactive:
            return
        print(f"\nplan: add a PATH block to {target} for {', '.join(map(str, missing))} "
              f"({SERVER_ENV_AFTER}; undo: loadout restore)")
        if not ui.confirm(ask, SERVER_ENV_QUESTION):
            return
    line = setup_vscode_path(bk)
    if line:
        out.status("VS Code PATH", f"{line}; {SERVER_ENV_AFTER}", "ok")
    elif flag:
        out.status("VS Code PATH", f"already set up in {target}", "ok")
```

def _key(version: str) -> tuple:
    return tuple(int(x) for x in re.findall(r"\d+", version))


def bundled_claude(platform: str | None = None) -> Path | None:
    """The Claude Code extension's bundled claude on this side (a local or Remote-WSL install, the newest version).
    A Windows window seen from WSL does not count: its claude.exe reads the Windows home."""
    found = [e for e in extensions({"claude": True}, platform, look=False)
             if e.install.where != "windows" and e.binary is not None]
    return max(found, key=lambda e: _key(e.version)).binary if found else None


def use_bundled_claude(on: bool | None = None) -> Path | None:
    """No claude on PATH and Claude Code on (on, else targets.json): loadout's own claude commands (claude plugin,
    claude mcp) run the extension's bundled binary. Returns it, or None (nothing registered)."""
    runner.FALLBACK.pop("claude", None)
    if on is None:
        from . import targets
        try:
            on = targets.claude_enabled()

            return None
    if not on or runner.have("claude"):
        return None
    found = bundled_claude()
    if found is not None:
        runner.FALLBACK["claude"] = str(found)
    return found
