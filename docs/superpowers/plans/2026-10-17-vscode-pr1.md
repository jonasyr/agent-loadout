# VS Code extensions PR 1 (detection and check rows) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** loadout finds VS Code, the Claude Code and Codex extensions and their bundled binaries on every OS and in WSL, and `loadout check` reports, per extension and window type, what it reads, what is missing and the fix; plus ADR 0032 and the how-to "Use loadout with VS Code".

**Architecture:** A new read-only module `cli/loadout/vscode.py` (installs, extensions, bundled binaries and versions, JSONC settings, the home each surface reads, the PATH a Remote-WSL window gives, MCP commands). `cli/loadout/check.py` gains three row builders that use it: `_vscode_surfaces`, `_vscode_path`, `_repo_mcp_paths`. Nothing here writes; Parts 2 and 3 of the spec (gap messages in bootstrap, fixes) are later PRs.

**Tech Stack:** Python 3.11+ standard library only; pytest with `fake_home` / `fake_runner`.

**Spec:** `docs/superpowers/specs/2026-10-17-vscode-extensions-design.md` (Part 1, Part 4's check rows and docs; PR 1).

## Global Constraints

- "Python 3.11+, standard library only in `cli/loadout/`."
- "Tests use the `fake_home` and `fake_runner` fixtures. Never touch the real `~/.claude`, `~/.claude.json`, `~/.codex` or `~/.config/loadout`." Tests also never read the real VS Code folders: every test that calls `vscode` clears `APPDATA`, `XDG_CONFIG_HOME` and `VSCODE_EXTENSIONS`.
- "External commands run only through `runner.run` with argument lists." The bundled Codex is asked only `--version`, with `timeout=15`.
- Spec: "Nothing here writes. With an agent off, nothing of that agent is read."
- Spec: "The VS Code checks report problems with MCP entries and never rewrite one."
- Spec: VS Code (stable) only; extension ids `anthropic.claude-code` and `openai.chatgpt`; Codex minimum `0.161`.
- Spec gap wording: "what is missing, what it means for the user, the fix". The Codex-extension gap names "use the Codex CLI alongside VS Code".
- The Remote-WSL PATH claim is from the docs ("no shell startup scripts are run") and not yet live-tested: the row says "may not find", never "cannot".
- Every check row added is `severity="warn"`: `loadout check` must not exit 1 because of VS Code.
- Conventional Commits, no AI attribution.

## Review Focus

1. A `settings.json` with comments, trailing commas, a BOM or CRLF must parse; one that does not parse must give `None`, never an exception that breaks `loadout check`.
2. Several version folders of one extension (`openai.chatgpt-26.715.31925-linux-x64` and `-26.715.61943-…`, `anthropic.claude-code-2.1.9` vs `2.1.10`): the newest by number, not by string.
3. A bundled Codex that hangs or prints no version: no warning about its version, and the check goes on.
4. With an agent off (`targets.json`), none of that agent's extensions is read or reported.
5. A committed `.mcp.json` that is not JSON, or has `mcpServers` that is not an object: no row and no crash; a secret-looking argument is never printed (only server names and the home prefix).

"""VS Code and the agents' extensions, read-only: where VS Code is, which agent extensions it has, their bundled
binaries, the settings that matter, the home each window reads (docs/superpowers/specs/2026-10-17-vscode-extensions-design.md)."""
from __future__ import annotations

import json
import os
import re
import sys
from dataclasses import dataclass
from pathlib import Path

from . import paths, runner, wsl

EXT_ID = {"claude": "anthropic.claude-code", "codex": "openai.chatgpt"}
LABEL = {"claude": "Claude Code", "codex": "Codex"}
WHERE = {"local": "", "windows": "Windows window", "remote-wsl": "Remote-WSL window"}
CODEX_MIN = (0, 161)
_FOLDER_VERSION = re.compile(r"(\d+(?:\.\d+)+)")
_VERSION = re.compile(r"(\d+)\.(\d+)\.(\d+)")
_TRAILING_COMMA = re.compile(r",(\s*[}\]])")


@dataclass(frozen=True)
class Install:
    where: str  # "local", "windows" (VS Code on Windows, seen from WSL) or "remote-wsl" (its server in WSL)
    user_dir: Path | None  # <...>/Code/User: settings.json and profiles/; None for the Remote-WSL server
    extensions: Path


@dataclass(frozen=True)
class Extension:
    agent: str  # "claude" or "codex"
    install: Install
    folder: Path
    version: str
    binary: Path | None  # the bundled agent binary; None when this build has none


def _user_dir(home: Path, platform: str) -> Path:
    if platform == "win32":
        return Path(os.environ.get("APPDATA") or home / "AppData" / "Roaming") / "Code" / "User"
    if platform == "darwin":
        return home / "Library" / "Application Support" / "Code" / "User"
    return Path(os.environ.get("XDG_CONFIG_HOME") or home / ".config") / "Code" / "User"


def _exists(install: Install) -> bool:
    return install.extensions.is_dir() or (install.user_dir is not None and install.user_dir.is_dir())


def installs(platform: str | None = None, win_home: Path | None = None) -> list[Install]:
    """VS Code installs this loadout can see: the local one; in WSL also VS Code on Windows (win_home, else found
    through wsl.windows_home) and its Remote-WSL server."""
    platform = platform or sys.platform
    home = paths.home()
    ext_env = os.environ.get("VSCODE_EXTENSIONS")
    found = [Install("local", _user_dir(home, platform), Path(ext_env) if ext_env else home / ".vscode" / "extensions")]
    if wsl.detect() is not None:
        win = win_home or wsl.windows_home()
        if win is not None:
            found.append(Install("windows", wsl.vscode_settings(win).parent, win / ".vscode" / "extensions"))
        found.append(Install("remote-wsl", None, home / ".vscode-server" / "extensions"))
    return [i for i in found if _exists(i)]


def newest(folder: Path, ext_id: str) -> tuple[Path, str] | None:
    """The extension's newest version folder (by number: 2.1.10 after 2.1.9) and its version."""
    try:
        entries = list(folder.iterdir())
    except OSError:
        return None
    best = None
    for entry in entries:
        name = entry.name.lower()
        if not name.startswith(ext_id + "-"):
            continue
        m = _FOLDER_VERSION.match(name[len(ext_id) + 1:])
        if not m or not entry.is_dir():
            continue
        key = tuple(int(x) for x in m.group(1).split("."))
        if best is None or key > best[0]:
            best = (key, entry, m.group(1))
    return None if best is None else (best[1], best[2])


def _binary(agent: str, folder: Path) -> Path | None:
    if agent == "claude":
        candidates = [folder / "resources" / "native-binary" / n for n in ("claude", "claude.exe")]
    else:
        try:
            candidates = [d / n for d in sorted((folder / "bin").iterdir()) for n in ("codex", "codex.exe")]
        except OSError:
            candidates = []
    return next((p for p in candidates if p.is_file()), None)


def extensions(on: dict[str, bool], platform: str | None = None, win_home: Path | None = None) -> list[Extension]:
    """The agent extensions of the agents that are on, one per install that has it."""
    out = []
    for install in installs(platform, win_home):
        for agent, ext_id in EXT_ID.items():
            if not on.get(agent):
                continue  # an agent that is off: nothing of it is read
            hit = newest(install.extensions, ext_id)
            if hit is not None:
                out.append(Extension(agent, install, hit[0], hit[1], _binary(agent, hit[0])))
    return out


def bundled_version(ext: Extension) -> str | None:
    """The version of the agent the extension runs: Claude Code's is the extension's own; Codex's is asked."""
    if ext.agent == "claude":
        return ext.version
    if ext.binary is None:
        return None
    res = runner.run([str(ext.binary), "--version"], timeout=15)
    m = _VERSION.search(res.stdout) if res.ok else None
    return m.group(0) if m else None


def too_old(version: str) -> bool:
    m = _VERSION.match(version)
    return m is not None and (int(m.group(1)), int(m.group(2))) < CODEX_MIN


def read_jsonc(path: Path) -> dict | None:
    """A VS Code settings file (JSONC: comments, trailing commas, a BOM) as a dict; None when it cannot be read."""
    try:
        text = path.read_bytes().decode("utf-8-sig")
    except (OSError, UnicodeDecodeError):
        return None
    masked = wsl._mask_comments(text)
    pieces, last = [], 0
    for m in re.finditer(r'"(?:[^"\\]|\\.)*"', masked):  # trailing commas outside strings only
        pieces.append(_TRAILING_COMMA.sub(r"\1", masked[last:m.start()]))
        pieces.append(m.group(0))
        last = m.end()
    pieces.append(_TRAILING_COMMA.sub(r"\1", masked[last:]))
    try:
        data = json.loads("".join(pieces))
    except ValueError:
        return None
    return data if isinstance(data, dict) else None


def settings_files(install: Install) -> list[Path]:
    """The user settings file of an install (the Remote-WSL server's machine settings for its server)."""
    if install.user_dir is None:
        return [install.extensions.parent / "data" / "Machine" / "settings.json"]
    return [install.user_dir / "settings.json"]


def setting(install: Install, key: str) -> object | None:
    for path in settings_files(install):
        data = read_jsonc(path)
        if data is not None and key in data:
            return data[key]
    return None


def row_name(ext: Extension) -> str:
    where = WHERE[ext.install.where]
    return f"VS Code ({LABEL[ext.agent]}{', ' + where if where else ''})"
```

# 0032. VS Code extensions are a surface of an agent

- Status: Accepted
- Date: 2026-10-17
- Source: [Design: VS Code extensions as a surface of each agent](../superpowers/specs/2026-10-17-vscode-extensions-design.md)

## Context

Many people use Claude Code and Codex only through their VS Code extensions, or next to the CLIs. Both extensions bundle their own agent binary and never use the one on PATH; the Codex extension installed on a test machine bundled codex 0.145, older than loadout needs. The Claude Code extension shares `~/.claude` with the CLI, plugins included. The Codex extension shares `config.toml`, `AGENTS.md`, skills, MCP servers and the login, but loads no plugins and has no `/hooks`. On Windows, a local VS Code window reads the Windows homes, which loadout in WSL never sets up. loadout looked only at the CLIs, so it could report a healthy setup that the user's editor did not see.

## Decision

loadout treats each extension as a surface of its agent: `targets.json` still says which agents are on, and for each agent that is on loadout finds its VS Code extensions, read-only (`cli/loadout/vscode.py`). `loadout check` reports per extension and window type what it reads and what it lacks, each with its fix; where a feature needs a CLI (Codex's plugins and `/hooks`), the fix is the CLI alongside VS Code. These rows are warnings, never failures. loadout changes no VS Code file and no MCP entry for this; fixes that write follow the repo-writes rules (plan, yes, backup, restore) and come with their own change.

## Consequences

- An extension-only user learns what their editor misses and how to get it, instead of a clean report that does not apply to them.
- Every check reads the newest extension folder again, because extensions update themselves; the bundled Codex is asked `--version` once per check.
- What only the installed code shows (the binary resolution, a Remote-WSL window's PATH) is checked again in the live tour; the PATH row says "may not find" until then.
- Editors other than VS Code (Insiders, Cursor, VSCodium, Windsurf) are not covered.
```

# Use loadout with VS Code

Use this page if you work in VS Code with the Claude Code extension, the Codex extension, or both, with or without the CLIs. loadout sets up the same agent folders the CLIs read; this page says what each extension sees of that, what it lacks, and the fix. Why it works this way: [ADR 0032](../adr/0032-vscode-extensions-are-a-surface-of-an-agent.md).

## What each extension sees

Both extensions bring their own copy of the agent and do not use the `claude` or `codex` on your PATH.

| | Claude Code extension | Codex extension |
|---|---|---|
| Reads | `~/.claude` and `~/.claude.json`, like the CLI: rules, settings, plugins, hooks, MCP servers, `CLAUDE.md`, your login | `~/.codex` (or `$CODEX_HOME`), like the CLI: `config.toml`, `AGENTS.md`, `hooks.json`, MCP servers, your login; skills in `~/.agents/skills` |
| Lacks | Little: it does not run in VS Code's Restricted Mode (trust the folder) | Plugins: loadout's skills (such as `loadout:configure`), superpowers and plugin hooks do not load. `/hooks`: there is no command to approve hooks |
| Fix for what it lacks | Trust the workspace | Use the Codex CLI alongside VS Code (below) |

### The Codex CLI alongside VS Code

`loadout check` shows `VS Code (Codex)` with the warning "plugins do not load" when the Codex CLI is missing. The fix: install the Codex CLI with `loadout bootstrap --install`, open VS Code's terminal, run `codex` once and approve loadout's hooks in `/hooks`. Use `codex` in that terminal whenever you need a plugin skill; the extension and the CLI share your settings and login.

`loadout check` also warns when the extension's own Codex is older than 0.161: update the extension in VS Code's Extensions view.

## Windows and WSL

Which home an extension reads depends on the window:

| Window | Claude Code extension reads | Codex extension reads |
|---|---|---|
| A Remote-WSL window (`code .` from WSL) | the WSL `~/.claude` | the WSL `~/.codex` |
| A local Windows window | `%USERPROFILE%\.claude` | `%USERPROFILE%\.codex`, or the WSL `~/.codex` when `chatgpt.runCodexInWindowsSubsystemForLinux` is on ([the switch](wsl.md#when-your-only-codex-is-the-windows-one)) |

With loadout in WSL, open your repos with `code .` from WSL, so both extensions read what loadout set up. `loadout check` in WSL warns `VS Code (Claude Code, Windows window)` when the Claude Code extension is installed in VS Code on Windows, and the `VS Code` row when the Codex extension still runs the Windows Codex. To use the Windows window instead, set loadout up on Windows too with `bootstrap.ps1` ([Codex on both sides](wsl.md#codex-on-both-sides)).

### MCP servers in a Remote-WSL window

A Remote-WSL window runs no shell startup file, so folders that your shell adds to PATH (mise's shims, `~/.local/bin`) may be missing when the Codex extension starts an MCP server. `loadout check` warns `VS Code PATH` and names the servers. Fix: give the server an absolute command (for example `/home/you/.local/bin/serena`), or add the folder in `~/.vscode-server/server-env-setup`:

```bash
export PATH="$HOME/.local/bin:$HOME/.local/share/mise/shims:$PATH"
```

Then run "WSL: Restart" in VS Code, or reconnect. The Claude Code extension takes PATH from your login shell.

## A committed .mcp.json with your own path

A repo's `.mcp.json` is shared. When it starts a server from a path in one person's home (`/home/you/…`, `C:\Users\you\…`), teammates' agents cannot start it. `loadout check` in that repo warns `repo .mcp.json` and names the servers. Fix: register that server in local scope (`claude mcp add --scope local …`) or as your user-level server, and remove it from the committed file. loadout never changes the file.

## What loadout does not do here

loadout does not install or update extensions, trust a workspace, approve hooks, or change your MCP entries. An MCP entry you wrote, such as a Serena entry with an absolute command and a fixed `--project`, is used as it is ([Serena already set up](codex.md#what-stays-different)).
```
