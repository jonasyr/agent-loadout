# Tasklog 0.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Priorities and due dates for tasks, an importer, and a purge command, plus the docs for 0.4.

**Architecture:** Tasks 1–4 build on each other: Task 1 adds schema version 2 and migrates the user's existing `~/.local/share/tasklog/tasks.db` in place; Task 2 changes the `Store` API (new `Task` fields, new `add`/`list` signatures) that Tasks 3 and 4 call. Tasks 5–7 are independent text edits with the complete content given.

**Tech Stack:** Python 3.11, sqlite3, pytest.

---

### Task 1: Schema v2 with an in-place migration of existing databases

**Files:**
- Create: `src/tasklog/migrate.py`
- Modify: `src/tasklog/store.py` (`Store.__init__` calls `migrate.upgrade`)
- Test: `tests/test_migrate.py`

Existing users have real task history in `tasks.db`; a failed migration must never lose it.

- [ ] **Step 1: Write failing tests** for: a v1 database (no `user_version`) gains `priority INTEGER DEFAULT 2` and `due REAL NULL`, keeps every row, and ends at `PRAGMA user_version = 2`; a crash between steps leaves the original file untouched (backup copy `tasks.db.v1.bak` written first, migration inside one transaction); running it twice is a no-op.
- [ ] **Step 2: Run them and see them fail**
- [ ] **Step 3: Implement `upgrade(db, path)`**: copy the file to `tasks.db.v1.bak` (refuse to continue if the copy fails), `BEGIN IMMEDIATE`, `ALTER TABLE` for both columns, set `user_version`, `COMMIT`; on any error `ROLLBACK` and re-raise. Decide how to handle a database newer than v2 (refuse with a clear message).
- [ ] **Step 4: Run the tests; then migrate a copy of a real v1 database and compare row counts**
- [ ] **Step 5: Commit** `feat(store): schema v2 with in-place migration`

### Task 4: `tasklog import FILE`

Merges a JSON export (from `tasklog export`, 0.3 or 0.4 format) into the user's database through Task 2's `Store.add`. Duplicates (same title and `created`) are skipped. A malformed file must not leave a half-imported database.
